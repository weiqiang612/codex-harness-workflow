# v0.1.0-beta release notes

## What is included

- `init-harness` creates an agent-legible project scaffold and progressive-disclosure document tree.
- `new-task` turns one feature request into a confirmed specification, acceptance criteria, and
  dependency-aware tasks.
- `subagent-orchestrator` coordinates bounded Codex subagents, review, validation, and truthful
  task-state closeout.

## Intended use

This Beta is intended for developers using Codex on existing, non-trivial repositories. It is a
repository-level development Harness, not a general agent runtime, deployment system, or sandbox.

## Configuration defaults

- `init-harness` uses its documented development-standards URL by default. The user can replace or
  disable that source in the invocation.
- `new-task` uses Chrome MCP by default for UI acceptance. The user can name another available
  real-browser capability in the invocation.

## Known limitations

- Only Codex is supported and behavior on other coding agents is unverified.
- File ownership between subagents is instruction-enforced, not an operating-system sandbox.
- Task-number allocation is not concurrency-safe.
- Draft task state is not persisted before the implementation-approach checkpoint.
- A missing browser capability leaves UI acceptance incomplete.
- The project is distributed under the MIT License; modified copies must preserve the applicable
  copyright and license notices.

## Evidence

The repository includes an anonymized real-project case study and evidence bundle. These show
traceability and honest incomplete-state handling; they are not performance benchmarks.
